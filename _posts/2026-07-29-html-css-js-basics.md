웹페이지 하나가 화면에 뜨기까지 세 가지 언어가 각자 역할을 나눠 맡는다. HTML은 뼈대, CSS는 스타일, JS는 동작이다. 이 셋을 왜 굳이 나눠서 쓰는지부터 이해하면 이후 개념들이 훨씬 잘 붙는다. 뼈대와 스타일과 동작을 한 파일에 다 몰아넣으면 유지보수가 안 되기 때문에, 세 언어는 "찾아낼 수 있게" 이름표를 붙여두고(HTML의 id·class) 그 이름표를 CSS와 JS가 각각 참조하는 구조로 맞물려 있다.

## HTML — 구조 잡기

HTML 태그는 문서 구조, 메타데이터, 텍스트/콘텐츠, 리스트, 테이블, 폼, 미디어, 시맨틱 태그로 나뉜다. 이 중 눈에 보이지 않지만 중요한 게 메타데이터 태그다.

- `<meta>`: 검색엔진 노출 등 브라우저 동작에 영향을 준다
- `<link>`: CSS 파일을 연결한다
- `<script>`: JS 파일을 연결한다
- `<form>`: 사용자 입력을 서버로 전송한다

**id와 class는 왜 있을까?** 요소 자체에는 이름이 없다. `<div>`나 `<button>`만 봐서는 CSS나 JS가 "이 요소"를 콕 집어 가리킬 방법이 없다. 그래서 id(고유 식별자 하나)와 class(재사용 가능한 이름표)를 미리 붙여두고, CSS 셀렉터나 JS의 `querySelector`가 이 이름표를 보고 요소를 찾는다.

블록 엘리먼트는 한 줄 전체를 차지하고, 인라인 엘리먼트는 콘텐츠 크기만큼만 차지한다. `<img>`는 이미지 하나를 고정으로 보여주지만 `<picture>`는 디바이스 화면 크기에 따라 다른 이미지를 골라 보여줄 수 있어 반응형 이미지에 쓴다.

**시맨틱 HTML은 왜 쓸까?** `<div>`만으로도 레이아웃은 다 만들 수 있다. 하지만 `header`, `nav`, `aside`, `footer`, `main` 처럼 역할이 이름에 드러나는 태그를 쓰면 코드를 읽는 사람도, 검색엔진도, 스크린 리더도 구조를 바로 파악할 수 있다. 가독성과 접근성을 위한 선택이다.

반응형 웹은 뷰포트 메타 태그로 디바이스 너비 기준을 잡고, 픽셀 고정값 대신 `%`나 `vw/vh` 같은 상대값으로 크기를 표시해서 구현한다.

> 팁: VS Code에서 `.html` 파일을 만들고 `!` 또는 `html:5`를 입력하면 기본 템플릿이 자동 생성된다(Emmet 문법). 매번 `<!DOCTYPE html>`부터 손으로 칠 필요가 없다.

## CSS — 스타일 입히기

CSS를 적용하는 방법은 세 가지다.

1. **Inline** — 엘리먼트 안에 `style` 속성으로 직접 지정
2. **Internal** — `<head>` 안에 `<style>` 태그로 작성
3. **External** — 외부 `.css` 파일을 `<link>`로 연결

**실무에서는 왜 External만 쓸까?** Inline은 요소 하나하나에 스타일을 박아 넣는 방식이라 같은 스타일을 열 군데에 쓰면 열 번 다 고쳐야 한다. Internal은 그 파일 안에서만 재사용된다. External은 CSS 파일 하나를 여러 HTML 페이지가 공유할 수 있어서 디자인을 한 곳에서 관리할 수 있다. 그래서 구조(HTML)와 스타일(CSS)을 파일 단위로 완전히 분리하는 External 방식이 기본이 된다.

셀렉터에서 가상 클래스는 콜론 하나(`:hover`), 가상 요소는 콜론 두 개(`::before`)로 표기한다.

- **transform**: 이동·회전·확대/축소·기울이기 등 형태 자체를 변형한다 (`translate`, `rotate`, `scale`, `skew`)
- **transition**: 속성값이 바뀔 때 그 변화를 부드럽게 처리한다
- **animation**: `@keyframes`로 단계를 정의하고 `animation` 속성으로 적용한다

transform이 "어떻게 바뀔지"를 정의하는 거라면, transition은 "그 변화가 얼마나 부드럽게 일어날지"를 정하는 것이고, animation은 아예 여러 단계를 미리 짜놓은 시나리오라고 보면 구분이 쉽다.

CSS 변수는 `--변수명`으로 선언하고 `var(--변수명)`으로 불러 쓴다. 색상이나 간격처럼 반복되는 값을 한 곳에서 관리할 수 있다.

## JavaScript — 동작 붙이기

### 변수 선언: var, let, const

| 키워드 | 범위 | 재할당 | 재선언 |
|---|---|---|---|
| var | 함수 범위 | 가능 | 가능 |
| let | 블록 범위 | 가능 | 불가능 |
| const | 블록 범위 | 불가능 | 불가능 |

**요즘 var를 잘 안 쓰는 이유는 뭘까?** var는 함수 범위라서 `if`문이나 `for`문 블록 밖에서도 접근이 되고, 같은 이름으로 재선언까지 허용된다. 규모가 커지면 어디서 값이 바뀌었는지 추적하기 어려워진다. let/const는 블록 범위로 딱 그 중괄호 안에서만 살아있어서 실수를 줄여준다. 그래서 기본은 const, 재할당이 필요할 때만 let을 쓴다.

### 데이터 타입

Primitive(string, number, bigint, boolean, undefined, null, symbol)와 Reference(object, array, function)로 나뉜다.

symbol은 호출할 때마다 항상 새로운 고유값을 만들어내는 타입이다. 같은 이름으로 `Symbol('id')`를 두 번 만들어도 서로 다른 값 취급된다. 객체 프로퍼티 키가 다른 코드와 절대 충돌하지 않게 하고 싶을 때 쓴다.

### 비교 연산자: == vs ===

`==`는 느슨한 비교로, 타입이 달라도 형변환을 해서 값만 같으면 true다. `===`는 엄격한 비교로 타입까지 같아야 true다.

**왜 헷갈릴까?** `1 == '1'`은 true지만 `1 === '1'`은 false다. 문자열 `'1'`이 숫자 `1`로 형변환되기 때문이다. 이 형변환이 예상치 못한 버그를 만들기 쉬워서, 실무에서는 `===`를 기본으로 쓰고 정말 형변환이 필요한 경우에만 의도적으로 `==`를 쓴다.

비트 연산자는 `<<`(왼쪽 시프트), `>>`(오른쪽 시프트, 부호 유지), `>>>`(오른쪽 시프트, 0으로 채움)가 있다.

### 반복문: for...in vs for...of

- `for...in`: 객체의 **속성(키)**을 순회한다
- `for...of`: 배열, 문자열, Map, Set 같은 **이터러블의 값**을 순회한다

**왜 헷갈릴까?** 둘 다 생김새가 비슷하고 "in/of 한 글자 차이"라 이름만 보면 구분이 안 된다. 기준은 하나다. 객체의 키가 필요하면 in, 컬렉션 안의 값 자체가 필요하면 of. 배열에 for...in을 쓰면 인덱스가 문자열로 나오는 등 예상과 다르게 동작할 수 있어서, 배열은 되도록 for...of나 배열 메소드를 쓰는 게 안전하다.

### 함수: call by value vs call by sharing

함수를 정의할 때 괄호 안에 적는 건 parameter(매개변수), 함수를 호출할 때 실제로 넘기는 값은 argument(인수)다.

**call by value**는 원시 타입(string, number 등)을 넘길 때다. 함수 안에서 매개변수를 바꿔도 원본 변수는 영향을 받지 않는다. 값을 복사해서 넘기기 때문이다.

**call by sharing**은 객체나 배열을 넘길 때다. 함수 안에서 프로퍼티를 변경하면 원본에도 반영되지만, 매개변수 자체를 다른 객체로 재할당하면 원본은 그대로다.

```js
function updateCar(car) {
  car.price = 0;        // 원본 객체의 프로퍼티 변경 → 원본에 반영됨
  car = { price: 9999 }; // 매개변수 자체를 재할당 → 원본은 그대로
}
const myCar = { price: 1000 };
updateCar(myCar);
console.log(myCar.price); // 0
```

**왜 헷갈릴까?** "객체는 참조로 넘어간다"는 말만 듣고 재할당까지 원본에 반영될 거라 착각하기 쉽다. 정확히는 객체에 대한 참조값 자체가 값으로 복사되어 넘어간다. 그래서 프로퍼티 변경은 같은 객체를 가리키므로 반영되지만, 매개변수를 통째로 바꾸는 건 그 지역 변수가 다른 곳을 가리키게 될 뿐 원본과의 연결이 끊긴다.

### 배열과 오브젝트

배열은 `map`, `filter`, `reduce` 같은 메소드와 spread operator(`...`)를 주로 쓴다. 오브젝트는 `obj.name` 같은 프로퍼티, `obj.method()` 같은 메소드, 그리고 constructor로 구성된다.

예를 들어 물건 목록을 다루는 코드라면 목록 조회에 `filter`, 목록 렌더링에 `map`을 이렇게 쓸 수 있다.

```js
// 특정 가격 이하의 항목만 필터링
const cheapItems = items.filter((item) => item.price <= 2000);
// 배열을 순회하며 화면에 렌더링할 HTML 조각 생성
const listHTML = items.map((item) => `<li>${item.name} - ${item.price}만원</li>`).join('');
```

### 호이스팅 (Temporal Dead Zone)

var는 선언부만 끌어올려지고 초기값은 undefined로 채워진다. let/const도 호이스팅되긴 하지만, 초기화되기 전 구간(Temporal Dead Zone, TDZ)에서 접근하면 에러가 난다. 함수 선언식(`function foo(){}`)은 통째로 호이스팅되어 선언 전에 호출해도 동작하지만, 함수 표현식(`const foo = function(){}`)은 변수 호이스팅 규칙을 따르므로 선언 전에 호출하면 에러가 난다.

**왜 이런 게 있을까?** var로 선언한 변수를 선언문보다 앞에서 참조하면 에러 대신 `undefined`가 나온다. 이게 "선언했는데 왜 값이 없지"라는 혼란을 만든다. let/const는 아예 TDZ에서 접근을 막아버려서, "선언 전에 썼다"는 실수를 에러로 바로 잡아준다.

### 내장 객체

- **Date**: 날짜/시간을 다루는 내장 객체
- **Set**: 중복을 허용하지 않는 값의 집합, 배열 중복 제거에 자주 쓴다
- **Map**: 키-값 쌍을 저장하고 키로 어떤 타입이든 쓸 수 있다
- **Math**: `Math.random()`, `Math.floor()` 등
- **RegExp**: 특정 패턴의 문자열을 검사·추출·치환한다

### DOM과 이벤트 핸들러

`document.querySelector` 같은 메소드로 HTML 요소를 선택하고 조작하는 게 DOM 제어다. 이벤트를 등록하는 방법은 세 가지다.

1. HTML 속성 방식 — `<button onclick="handleClick()">`
2. DOM 프로퍼티 방식 — `el.onclick = handleClick` (핸들러 1개만 등록 가능, 나중에 등록한 게 이전 걸 덮어씀)
3. `addEventListener` — 같은 요소에 여러 핸들러를 동시에 등록 가능

**왜 addEventListener를 권장할까?** 앞의 두 방식은 요소마다 이벤트 핸들러를 하나만 가질 수 있다. 여러 기능을 붙이려면 하나의 함수 안에 다 몰아넣어야 한다. `addEventListener`는 같은 이벤트에 여러 개의 리스너를 독립적으로 추가·제거할 수 있어서 기능이 늘어나도 코드가 서로 얽히지 않는다.

```js
document.querySelector('#addBtn').addEventListener('click', () => {
  items.push(newItem);
  render();
});
```
