데이터 분석은 "데이터를 예쁘게 그려보는 일"이 아니라, 데이터를 가공해서 의사결정에 쓸 수 있는 수준까지 끌어올리는 일이다. 이 관점을 DIKW 가치사슬이 잘 보여준다. 데이터(가공 전 사실) → 정보(정리된 데이터) → 지식(패턴이 파악된 정보) → 지혜(지식을 바탕으로 한 판단) 순으로 가공될수록 더 높은 수준의 의사결정을 지원한다. 데이터 분석이 하는 일은 결국 이 사다리를 한 칸씩 올리는 것이다.

분석의 결과물도 수준이 나뉜다. 기술적 분석(무엇이 일어났나) → 진단적 분석(왜 일어났나) → 예측적 분석(앞으로 어떻게 될까) → 처방적 분석(그래서 어떻게 해야 하나) 순으로 난이도와 가치가 올라간다. 실무에서 "데이터 분석 하자"고 할 때 이 넷 중 어디를 목표로 하는지부터 정하지 않으면 방향이 흐트러지기 쉽다.

## 분석은 어떤 순서로 진행할까

분석 주제 선정 → 데이터 준비 → 분석 기법 선택이 큰 틀이고, 데이터 준비 단계 안에서는 데이터 탐색 및 문제 진단 → 결측치 처리 → 스케일 조정 → 범주형 인코딩 → 이상치 처리 → 분포 변환 순으로 전처리가 이어진다. 이 전처리 워크플로우는 아래에서 하나씩 다시 짚는다.

관련 직무도 이 흐름 안에서 나뉜다. Data Scientist는 분석·예측 모델을 개발하고, Data Engineer는 그 모델이 돌아갈 수 있도록 데이터 처리 파이프라인을 구축한다.

## 변수를 보는 관점

같은 대상이라도 "고객 만족도"처럼 비즈니스 목적으로 정의한 개념적 정의와, 그것을 실제로 측정 가능한 값(설문 점수 1~5)으로 바꾼 조작적 정의는 다르다. 분석은 조작적 정의로 변환된 변수를 가지고 진행한다.

변수는 분석 대상이 되는 것이고, 속성은 변수가 가질 수 있는 개별 값이다. 변수가 성립하려면 속성이 최소 2개 이상 있어야 한다. 값이 하나뿐이면 변할 수 없으니 "변수"라 부를 이유가 없다.

**척도는 왜 구분해서 볼까?** 같은 숫자라도 그 숫자가 뭘 의미하는지에 따라 쓸 수 있는 분석 기법이 달라지기 때문이다.

- 범주형: 이진척도(성별처럼 둘 중 하나), 명목척도(순서 없는 카테고리), 순서척도(순서는 있지만 간격은 의미 없음, 예: 학년)
- 연속형: 구간척도(간격은 의미 있지만 0이 "없음"을 뜻하지 않음, 예: 온도), 비율척도(0이 진짜 "없음"을 의미, 예: 매출)

비율척도인지 구간척도인지가 헷갈리기 쉬운데, 기준은 "0이 진짜 없다는 뜻인가"다. 온도 0도는 온도가 없다는 뜻이 아니지만, 매출 0원은 진짜 매출이 없다는 뜻이다.

**파생변수와 Lag변수**도 여기서 같이 정리하면 좋다. 파생변수는 기존 변수를 가공·결합·변환해서 새로 만든 변수로, 모델 성능에 기여하는 정도가 크다. Lag변수(시차변수)는 과거 시점의 값을 현재 시점의 변수로 끌어다 쓰는 것으로, 주가나 매출처럼 시간에 따라 이어지는 데이터에 쓴다. 분석단위는 데이터셋에서 한 행이 무엇을 대표하는지를 뜻한다. 고객 이탈을 예측한다면 분석단위는 "고객" 한 명이 된다.

## EDA vs CDA — 가설이 먼저냐 데이터가 먼저냐

**왜 헷갈릴까?** 둘 다 데이터를 들여다보는 과정이라 비슷해 보이지만 순서가 반대다. EDA(탐색적 데이터 분석)는 가설 없이 데이터를 먼저 살펴보며 패턴이나 관계를 발견해나가는 과정이고, CDA(확정적 데이터 분석)는 이미 세운 가설을 데이터로 검증하는 과정이다. "데이터를 보고 가설을 세우느냐" vs "가설을 세우고 데이터를 보느냐"로 구분하면 헷갈리지 않는다.

## 기술통계량으로 데이터 감 잡기

데이터를 세 가지 축으로 요약한다.

- 중심화: 평균, 중앙값, 최빈값
- 퍼짐: 표준편차, 변이계수, 범위
- 쏠림: 왜도, 첨도, 사분위수

박스플롯으로 이상치를 판단할 때는 제3사분위수 + 1.5×IQR을 넘거나 제1사분위수 − 1.5×IQR보다 작으면 이상치로 본다.

**표준정규분포(Z-score)는 왜 쓸까?** 시험 점수가 A반은 평균 70·표준편차 5, B반은 평균 60·표준편차 15라면, 두 반의 80점을 그냥 비교할 수 없다. 분포의 모양이 서로 다르기 때문이다. `(값 − 평균) / 표준편차`로 변환하면 평균 0, 표준편차 1인 공통 기준으로 맞춰져서 서로 다른 분포에 속한 값도 비교할 수 있게 된다.

## 전처리: 스케일링과 인코딩

**스케일링은 왜 모델마다 중요도가 다를까?** KNN처럼 거리 기반으로 작동하는 모델은 변수 간 값의 범위 차이가 그대로 거리 계산에 영향을 준다. 예를 들어 "나이(0~100)"와 "연소득(0~1억)"을 그대로 쓰면 소득 차이가 거리를 압도해버린다. 그래서 Z변환, Min-Max, 로그·제곱근 변환 등으로 범위를 맞춰준다. 반면 트리 계열 모델(랜덤포레스트 등)은 값을 기준으로 가지를 나누는 방식이라 스케일에 상대적으로 덜 민감하다.

범주형 변수는 숫자가 아니므로 그대로 모델에 넣을 수 없어 인코딩이 필요하다. 순서가 없는 명목형 변수는 one-hot 인코딩(각 카테고리를 0/1 컬럼으로 분리), 순서가 있는 순서형 변수는 라벨 인코딩(순서를 숫자로 매핑)을 쓴다. one-hot을 순서형에 쓰면 순서 정보가 사라지고, 라벨 인코딩을 명목형에 쓰면 없는 크기 관계(예: 카테고리 3이 카테고리 1보다 크다는 잘못된 의미)가 생겨버린다.

## 상관분석 — 관계의 방향과 세기 보기

상관계수는 -1~1 사이 값으로, 산점도로 방향성을 먼저 눈으로 확인한 뒤 정량화하는 게 순서다.

**해석할 때 조심할 점 네 가지**가 있다. 첫째, 비선형 관계는 상관계수가 못 잡아낸다(U자 형태 관계인데 상관계수는 0에 가깝게 나올 수 있다). 둘째, 이상치 하나에 값이 크게 흔들린다. 셋째, 교란요인이 숨어 있을 수 있어 편상관계수로 보정해야 할 때가 있다. 넷째, 그리고 가장 중요한 것 — **상관관계는 인과관계가 아니다.** 아이스크림 판매량과 익사 사고가 같이 늘어난다고 아이스크림이 사고를 일으키는 게 아니라, 여름이라는 제3의 요인이 둘 다를 늘린 것이다.

상관분석은 회귀분석 이전 단계로도 쓰인다. 변수 간 상관이 너무 높으면 다중공선성 문제가 생기고, 변수가 너무 많으면 차원의 저주가 생기는데, 상관분석으로 이런 변수를 미리 걸러낼 수 있다.

## 회귀분석 — 관계를 식으로 만들기

회귀분석은 목적이 둘로 나뉜다. 추론(변수 간 관계와 영향력을 파악하는 것, F통계량·p-value로 검증)과 예측(Y값을 정확히 맞히는 것, MAPE·RMSE로 평가)이다. 목적에 따라 뒤에서 다룰 도구도 달라진다.

회귀선을 찾는 기본 방법은 최소제곱법으로, 잔차(실제값과 예측값의 차이) 제곱합이 최소가 되는 직선을 찾는다.

**결과를 검증할 때 보는 지표**는 이렇다. F통계량의 유의확률이 0.05 미만이면 회귀식 전체가 유의하다는 뜻이고, 개별 계수의 p-value가 0.05 미만이면 그 변수가 유의하다는 뜻이다. Adjusted R²는 모델의 설명력을 나타낸다.

**회귀분석의 기본 가정 4가지**도 같이 정리한다. 선형성(X와 Y가 선형 관계), 독립성(변수 간 다중공선성이 없음), 등분산성(잔차의 분산이 일정함), 정규성(잔차가 정규분포를 따름). 이 가정이 깨지면 계수 추정이나 유의성 검증 결과를 그대로 믿기 어렵다.

### 상관분석 vs 회귀분석

| 구분 | 상관분석 | 회귀분석 |
|---|---|---|
| 표현 방식 | 상관계수 | 회귀식 |
| 변수 관계 | 대등한 관계 | 원인(X)-결과(Y) |
| 예측 가능 여부 | 불가능 | 가능 |
| 활용 순서 | 회귀분석 이전 | 상관분석 이후 |

**둘을 왜 헷갈릴까?** 둘 다 "변수 사이의 관계"를 본다는 점은 같아서 그렇다. 차이는 상관분석은 두 변수를 대등하게 보고 "얼마나 같이 움직이는가"만 말해줄 뿐 예측은 못 하지만, 회귀분석은 원인과 결과를 구분해서 식을 세우기 때문에 새로운 X값이 주어지면 Y를 예측할 수 있다는 점이다.

### statsmodels vs scikit-learn

목적이 다른 두 라이브러리다. statsmodels는 추론이 목적이라 F통계량과 p-value 같은 통계적 검증 결과를 제공한다. scikit-learn은 예측 성능을 극대화하는 게 목적이라 유의성 검증 기능은 따로 없다. "이 변수가 통계적으로 의미가 있는가"를 보고 싶으면 statsmodels, "얼마나 정확히 맞히는가"가 중요하면 scikit-learn 쪽에 가깝다.

## 데이터 분할과 과적합

모델을 만들 때는 데이터를 Train/Validation/Test로 나눈다. **Test Set은 왜 튜닝 기준으로 쓰면 안 될까?** Test Set은 "한 번도 안 본 데이터에서 얼마나 잘하는가"를 확인하는 최종 시험지 역할이다. 튜닝 과정에서 Test Set 성능을 계속 들여다보며 모델을 고치면, 결국 그 시험지에 맞춰 공부한 꼴이 되어 실제 성능을 과대평가하게 된다. 그래서 튜닝은 Validation Set으로 하고, Test Set은 마지막에 딱 한 번만 확인한다.

과적합은 Train 성능은 높은데 Test 성능은 낮은 현상이다. 모델이 학습 데이터의 패턴이 아니라 노이즈까지 외워버린 상태다.

Baseline 모델은 내가 만든 모델의 성능을 비교할 기준이고, Naive 모델은 별도 학습 없이 단순한 규칙만으로 예측하는 모델이다. 해커톤에서 전날 주가를 그대로 다음날 예측값으로 쓴 Naive 모델이 딥러닝 모델보다 성능이 좋았던 사례가 있었는데, 아무리 복잡한 모델을 써도 단순한 기준선을 못 이기면 그 모델은 의미가 없다는 걸 보여주는 사례다.

## 실습 — 주택가격 회귀 예측

OLS(잔차 제곱합이 최소가 되는 직선을 찾는 회귀) 모델을 만들고, MAPE(예측값이 실제값에서 평균적으로 몇 % 벗어났는지)로 성능을 평가했다.

```python
import statsmodels.api as sm

X = sm.add_constant(X_train)  # 절편(intercept) 추가
model = sm.OLS(y_train, X).fit()
print(model.summary())  # F통계량, p-value, Adjusted R² 확인
```

## 실습 — 식당 팁 예측 (Tips 데이터셋)

전처리 워크플로우를 그대로 적용해본 실습이다.

1. 데이터 분할 7:3
2. 결측값 확인 (없음)
3. 이상치 처리 — Z-score 기준으로 `total_bill`, `size`, `per_person_bill` 처리
4. 분포 변환 — 연속형 변수 3종 로그 변환
5. 데이터 스케일링 — Standard Scaler 적용
6. 인코딩 — 범주형 변수 6종 One-Hot 인코딩
7. 변수 선택 — `P>|t|` 값이 0.05 이상인 변수 8종 제거

```python
# 변수 선택: 유의하지 않은 변수 제거
insignificant_vars = model.pvalues[model.pvalues >= 0.05].index
X_selected = X.drop(columns=insignificant_vars)
```

전처리 순서(탐색 → 결측치 → 스케일 → 인코딩 → 이상치 → 분포 변환)와 실습에서 실제로 밟은 순서가 정확히 일치하지는 않는데, 실무에서는 데이터 상태에 따라 순서를 유연하게 조정한다. 다만 스케일링과 인코딩을 먼저 맞춰두고 이상치·분포를 손보는 흐름 자체는 같다.
